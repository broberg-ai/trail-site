How Trail Works

The Trail Glossary

Every Trail term in one place — from Brain, Neuron and Source to the Curation Queue, Lint and hybrid search — in plain language, the same definitions the Trail app uses.

How Trail Works · trail by broberg.ai · October 3, 2026
TL;DRThe whole article in 3 points
  1. Trail's vocabulary in one place: 58 terms, each in a few plain sentences, alphabetical.
  2. A Brain is one knowledge base; it holds Sources and the Neurons compiled from them, and a Curator decides what goes in.
  3. The list is generated from the same file the Trail app uses, so the app and this page always agree.

Trail has its own vocabulary — Brains, Neurons, Sources, the Curation Queue — and most words mean something precise. This glossary is the same list the Trail app shows its users, generated from the same file, so the two can never disagree.

A

Action

One of the resolution options on a Candidate. Default Candidates have Approve + Reject; richer Candidates (contradiction, orphan, stale) carry producer-specific Actions like "Retire Neuron", "Link to sources", "Dismiss as false positive". Each Action has a plain-language explanation describing what happens when you click it.

See also: Candidate, Effect

Answer feedback

The thumbs up, thumbs down and flag buttons under a chat answer — in the admin chat and in the embedded widget. Each click lands in the Curator's Queue together with the question, the answer, the cited Neurons and the reader's reason, so a wrong answer can be traced back and fixed in the Brain.

See also: Chat, Curation Queue, Curator, Chat widget

API key

A secret token that lets your own website, script or AI assistant talk to Trail — search, retrieve, chat or post knowledge. The full key is shown only once when you create it. Revoking it cuts off every integration using it immediately. Callers with an API key never see a Brain's internal Neurons.

See also: Audience, Chat widget, Connector, Tenant

Approve

The primary "yes, commit this" action on a Candidate. Triggers the effect behind the Action (create Neuron, update Neuron, archive, etc.) and logs a wiki_event with the Curator as actor. Every Candidate has at least one approve-effect action; contradiction and orphan findings replace it with more specific affirmative actions like Reconcile or Auto-link sources.

See also: Candidate, Action, Effect, Curator

Archive

Soft-delete a Neuron or Source. The document stays in the database (its data, metadata, and history are preserved) but disappears from the active lists. Reversible at any time from the Archived tab. Different from hard-deletion: Archive preserves the audit trail, links pointing to the archived Neuron become broken links until cleaned up, and the file on disk stays intact for Sources.

See also: Neuron, Source, Effect

Audience

Who is asking, which decides what they may see. Curator (you in the admin) sees everything. Tool (a site's own AI fetching from Trail) and public (a chat shown directly to visitors) never see heuristic Neurons or Neurons tagged internal. A caller with an API key gets tool by default and can narrow its audience, never widen it. Each Brain can add its own persona text for tool and public answers.

See also: API key, Heuristic Neuron, Chat widget, Search

Auto-approve

Policy that approves a Candidate without curator review. Fires for trusted pipelines (e.g. ingest-summary) and for candidates above a confidence threshold. Human-originated candidates never auto-approve by design — people click "submit", machines emit confidences.

See also: Candidate, Curator, Confidence

Auto-link

A one-click action on an Orphan Neuron finding. The LLM reads the Neuron's content, reviews the best-matching Sources in the same Brain (pre-filtered by keyword overlap), and proposes the 1–3 Sources the Neuron's claims most likely came from. If confident, it adds them to the Neuron's sources and the orphan alert disappears. If nothing matches clearly, it asks the Curator to link manually. Uses a small Mistral model (EU) to keep the cost predictable.

See also: Orphan Neuron, Frontmatter, Source, Reference, LLM

B

Backlink

The inverse of a Neuron-link. If Neuron A contains [[B]], then B has a backlink FROM A. Shown on the Neuron reader as "N Neurons link here" — lets the Curator see how interconnected a Neuron is.

See also: Neuron, Neuron-link, Typed Edge, Reference

Brain

One knowledge base inside Trail — the Sources you add, the Neurons compiled from them, and the curator decisions that shaped them, held together by one topic or project. A tenant can have many Brains ("my reflexology Brain", "my iOS notes Brain"). Until September 2026 the admin called this unit "a Trail"; Trail is now the name of the product only.

See also: Trail, Tenant, Neuron, Source, Curator

Brain version

A named point in a Brain's history that you can roll back to. Trail sets one automatically before changes to knowledge are written (at most one every 15 minutes, so a big sync gives one version, not a hundred), and you can set your own. Before a rollback you are shown exactly what will change, and Trail saves the current state as a version first, so the rollback itself can be undone.

See also: Brain, Archive, Neuron

C

Candidate

A single proposed change to a Brain — a new Neuron, an edit, an archive, or an alert from Lint. Each Candidate has a status (pending, approved, rejected) and a set of Actions the Curator can choose from.

See also: Curation Queue, Action, Fingerprint

Chat

Asking a Brain a question in plain language. Trail finds the Neurons that fit, writes an answer from them and shows which Neurons it used. Superseded Neurons and Neurons whose confidence has faded below 0.3 are left out, so old knowledge doesn't creep into new answers. A conversation can be saved as a Source, which compiles it back into the Brain.

See also: Search, Neuron, Superseded, Memory fading, Answer feedback, Chat widget

Chat widget

A ready-made chat box () you can put on your own website, so visitors ask questions and get answers from your Brain with citations and feedback buttons. Today it talks to Trail through a small proxy on your own server, which keeps your API key out of the browser.

See also: Chat, API key, Audience, Answer feedback

Chunk

A short piece of a document — roughly 500 tokens, split along paragraphs and headings — that search indexes separately. Each chunk remembers which heading it sits under, so a search hit can point to the exact section instead of just the whole document.

See also: Search, FTS, Ingest, Source

Compile

The LLM step that turns extracted Source text into one or more Neurons. The model gets the Source text, the Brain's language, its existing tags and the entities it already knows, and writes claim-dense pages — each with frontmatter (title, sources, tags, type) and [[Neuron-links]] to related pages. The result lands as Candidates in the Queue; the auto-approval policy decides whether they go in without a human click. In the cloud the default model is Mistral (EU), a small model first with a larger one as fallback; a Brain can be set to another model in its settings. Distinct from Ingest (the whole pipeline around compile), Retry (re-runs everything) and Re-ingest (re-runs only compile).

See also: Ingest, Source, Neuron, Re-ingest, Retry, Auto-approve

Confidence

A 0-1 number on every machine-generated Candidate representing how sure the pipeline is. High confidence (≥0.8 by default) can auto-approve via policy; lower confidence lands pending for Curator review. Human-submitted candidates always land pending regardless.

See also: Candidate, Auto-approve

Connector

The route a piece of knowledge came into a Brain by — a file upload, the API, a saved chat, a lint finding, a direct edit by the Curator, an AI coding tool via MCP, and others. Every Queue item and Neuron shows "Created via …", and the Queue can be filtered by connector. Slack, Discord, Notion, GitHub and Linear are on the roadmap, not live.

See also: Curation Queue, Candidate, Source, New version becomes canon, API key

Contradiction

Two Neurons whose claims cannot both be true under standard reading. Detected by pairwise LLM comparison after a new or updated Neuron is approved. If one side clearly wins (clearly higher confidence and at least as many Sources), Trail supersedes the weaker one automatically; otherwise the Curator decides: retire one, reconcile manually, flag the Source, or dismiss as a false positive. A new version of the same Source is not a contradiction — it becomes the new canon.

See also: Neuron, Lint, Action

Credits

The unit Trail uses to show what AI work costs your tenant. Each time Trail calls a language model for you — compiling a Source, answering a chat, running a check — the actual cost is deducted, one credit per US cent. The balance and recent use are on the Cost page. Buying extra credits in the app is not live yet.

See also: Tenant, LLM, Compile

Curation Queue

The list of pending changes waiting for the Curator's decision. Every write into a Brain (new Neuron, edit, archive, lint alert) lands here first; the Queue is the ONLY path that can modify Neurons.

See also: Candidate, Curator, Auto-approve

Curator

The human who decides what lives in a Brain. Curators review candidates in the Queue, approve or reject them, and occasionally edit Neurons directly. The Curator is the source of truth — the LLM proposes, the Curator disposes.

See also: Curation Queue, Candidate

D

Dismiss

Discard a Candidate without committing its change. Used when a lint finding is a false alarm, a chat-answer turned out to be wrong, or the Curator disagrees with a compiler-proposed update. Leaves the target Neuron unchanged. Under the default Trusting Lint Policy, dismissed lint findings don't re-fire — under Strict, they may re-qualify on the next run.

See also: Candidate, False Positive, Lint Policy

E

Effect

The engine-level operation behind an Action. Examples: approve (commit the candidate's content), reject (discard), retire-neuron (archive a specific page), flag-source (mark a Source as untrustworthy), acknowledge (mark as handled manually). Multiple Actions can share an effect — a contradiction's "Retire A" and "Retire B" both use retire-neuron with different documentId args.

See also: Action, Candidate

F

False Positive

A Lint finding that isn't actually a problem. The detector got it wrong — different phrasing looked like a contradiction, an intentionally-axiomatic page looked like an orphan, an evergreen reference looked stale. Dismissing as false positive blocks the finding from re-surfacing (in Trusting policy mode).

See also: Lint, Action, Lint Policy

Fingerprint

A stable identifier for a Lint finding, used to dedupe re-runs. A nightly Lint pass that finds the same orphan Neuron as yesterday skips re-emitting it. Includes the Neuron's version so a substantive rewrite creates a fresh fingerprint that bypasses old suppressions.

See also: Lint, Lint Policy

Frontmatter

The YAML block at the top of every Neuron, between two --- lines. Holds structured metadata: title, tags, date, and sources: [...] — the filenames the Neuron's claims came from. The reference extractor reads sources on save and writes the document_references rows that the backlink graph + orphan-detector rely on. Missing sources → Neuron shows up as an orphan on next Lint run.

See also: Neuron, Reference, Source, Orphan Neuron

FTS

Full-Text Search — the keyword-based search engine indexed over every Neuron's content + title + tags. Trail uses SQLite's FTS5 module (built in, no external service). FTS powers (1) the search bar in admin, (2) chat's context-retrieval (which Neurons relate to this question?), (3) lint's peer-discovery (which Neurons might contradict this one?). FTS is keyword-fast, not semantic — it matches words, not meanings. Auto-syncs via DB triggers when Neurons are created/edited/archived, so the index is always fresh. On a Brain with hybrid search switched on, search and chat combine FTS with meaning-based matching (see Search).

See also: Search, Chat, Lint, Peer, Top-K

H

Heuristic Neuron

A Neuron that holds a rule of thumb or a way of working ("always clarify the question before answering") rather than a fact. Its confidence drops the longer it goes unedited; below 0.3 it counts as faded and chat leaves it out, unless it is pinned. Heuristics are internal: external integrations never see them.

See also: Neuron type, Pin, Memory fading, Audience

I

Ingest

The process of reading a new Source, extracting its text, chunking it for search, and compiling one or more Neurons from it. Ingest produces ingest-summary candidates that auto-approve if confidence is high enough.

See also: Compile, Source, Neuron, Auto-approve, Retry, Re-ingest

L

Link Check

The list of [[Neuron-links]] in a Brain that point to a Neuron that doesn't exist. Where Trail can guess the intended target it suggests a fix: accept it to rewrite the link, dismiss it to keep the link as intended, or rescan after bulk edits.

See also: Neuron-link, Backlink, Lint

Lint

Background scan of a Brain for structural problems — orphan Neurons (no citations), stale Neurons (untouched too long), broken links, faded heuristics and contradictions (two Neurons with conflicting claims). Findings land as Candidates in the Queue; Lint never edits anything itself. Runs on a schedule set per Brain — weekly by default — and reactively when new Neurons arrive. Each check can be switched off per Brain.

See also: Orphan Neuron, Stale Neuron, Contradiction, Fingerprint

Lint Policy

Per-Brain setting controlling what happens to rejected Lint findings. "Trusting" (default) permanently suppresses them — no nag-loop. "Strict" lets them re-fire on the next Lint pass for a second review. Versioned fingerprints re-qualify findings after the Neuron has actually been edited, independent of policy.

See also: Lint, Fingerprint, False Positive

LLM

Large Language Model — the AI that does the heavy lifting inside Trail. It compiles Neurons from Sources, writes chat answers, describes images and checks Neurons for contradictions. In the cloud, Trail runs its language models at Mistral in the EU, and the fallback models are EU too — if Mistral is down, the job fails visibly instead of sending your data outside the EU. The Curator is always the final authority: the LLM proposes, the Curator disposes.

See also: Ingest, Neuron, Source, Curator, Lint

M

Memory fading

Each Neuron has a live confidence between 0 and 1, recalculated every night from how old it is, how many Sources back it, whether it is contradicted, and how often it is cited and read. Knowledge that is never used slowly weighs less in chat and search; it is never deleted. Fading is paused for a new Brain until you turn it on — so nothing fades before the site using the Brain is in real use. How fast each Neuron type fades can be adjusted on the Health page.

See also: Pin, Superseded, Heuristic Neuron, Chat, Neuron type

N

Neuron

A compiled page inside a Brain — a short, claim-dense markdown document generated from one or more Sources. Neurons link to each other with [[Neuron-links]] and cite Sources via frontmatter.

See also: Trail, Source, Backlink

Neuron type

What kind of knowledge a Neuron holds, read from the folder it lives in: concept, entity (a person, place or product), synthesis, comparison, source summary, saved query, session, heuristic, the Brain's glossary — or a plain note if it fits none of them. The type decides how fast a Neuron fades and who may see it.

See also: Neuron, Heuristic Neuron, Memory fading, Audience

Neuron-link

The [[...]] double-bracket syntax that links one Neuron to another inside a Brain. The text between the brackets is slugified to resolve against a target filename — [[Orphans + Stale]] finds orphans-stale.md. Neuron-links build the graph that powers the Chat's context-gathering, the Backlink view in the reader, and the orphan-detector's "no one links here" signal. How to author one: type [[Target Neuron Title]] directly in any markdown content field — the Neuron editor, the "+ New" modal, a Work item's Description (Task / Bug / Milestone / Decision), or the save-dialog when you pin a Chat answer as a Neuron. The backlink extractor resolves it on save; the new edge appears in the Graph and the target Neuron's "N Neurons link here" count ticks up. The ingest pipeline also writes Neuron-links automatically when compiling Sources, so the Curator rarely has to add them by hand. Optional typed form [[target|edge-type]] carries a semantic relation — cites (default, bare mention), is-a, part-of, contradicts, supersedes, example-of, caused-by — and colours the graph accordingly. Subject to link-integrity guarantees: an unresolvable link becomes a broken-link finding for the Curator, never a 404 on the reader.

See also: Neuron, Backlink, Slug (slugify), Contradiction, Orphan Neuron

New version becomes canon

When the same Source arrives again with new content — the same web page after an edit, or a file with the same name uploaded to the same Brain — the new version is the truth. It replaces the old one instead of landing as a contradiction in the Queue. It is on by default and can be switched off for the whole Brain or per connector. If an upload only shares its name with an older file, mark it "This is a new source" so it replaces nothing.

See also: Source, Superseded, Contradiction, Connector, Curation Queue

O

Orphan Neuron

A Neuron that cites no Sources in its frontmatter. Either the compiler wrote it without linking evidence, or the citation was lost in an edit. Lint flags it so the Curator can link the claims to Sources or archive the Neuron if its claims can't be defended.

See also: Neuron, Source, Lint, Reference

P

Peer

An OTHER Neuron in the same Brain that's structurally related to a given Neuron — typically a candidate for cross-checks like contradiction-lint. When Trail asks "does this Neuron contradict any of its peers?", "peers" = the top-K most semantically similar Neurons retrieved via FTS. Peers are not edges (those are wiki-backlinks); they're a per-query similarity-set assembled when needed and discarded after use.

See also: Neuron, FTS, Top-K, Lint, Neuron-link

Pin

Marking a Neuron as always true. A pinned Neuron is held at full confidence (1.0) and never fades, so it always counts fully in chat and search. Use it for core facts and definitions that don't get old.

See also: Memory fading, Heuristic Neuron, Superseded

Q

Quality control

A nightly check that measures, with numbers, whether a Brain's answers rest on its Sources and whether search finds the right Neuron. It asks trap questions the Brain should refuse, checks answer claims against Sources, and tests search ranking. It is off by default, runs at most once a day per Brain and stops at a budget cap you set (75 cents a night by default). Results and findings appear at the top of the Health page.

See also: Brain, Search, Chat, Lint

R

Re-ingest

Re-run ONLY the compile step against a Source's already-extracted content. Skips file-format extraction (no PDF re-parse, no image re-description) and goes straight to compile with the Brain's current model. Cheap and fast — useful when ingest hit a time or turn limit, or when the compile instructions have improved and you want existing Sources to benefit. If extraction itself failed, use Retry instead.

See also: Retry, Ingest, Source

Reconcile

A contradiction-resolution path that doesn't archive either Neuron. The Curator opens both in the editor and writes a new, merged Neuron that honors both sources' claims — e.g. "under condition X, A is true; under condition Y, B is true." Both original Neurons then get Archive'd or rewritten to reference the reconciled version. Canonical Danish: Forlig (not "Afstem" or "Forene" — those suggest voting or simple concatenation, which this isn't).

See also: Contradiction, Neuron, Curator, Archive

Reference

A tracked citation from a Neuron to a Source (provenance — "this claim came from this document") OR a [[Neuron-link]] from a Neuron to another Neuron (navigation — "see also"). Two separate graphs; the Curator sees both as one interconnected whole.

See also: Neuron, Source, Backlink, Frontmatter

Retire

A contradiction-specific variant of Archive. When two Neurons contradict each other, the Curator picks which one to retire — effectively the same action as Archive, but scoped to the contradiction resolution so the audit trail records WHY the Neuron was taken out of circulation. Canonical Danish translation: Arkivér (not "Pensionér" — that sounds like a person retiring from work, misleading here).

See also: Archive, Contradiction, Neuron

Retry

Re-run the ENTIRE pipeline for a Source — re-extract the file (PDF text, DOCX HTML, PPTX slides, XLSX cells), re-chunk, and re-ingest. Use this when extraction itself failed (corrupt PDF, silent pdfjs hang, vision-API hiccup) or when you've replaced the underlying file bytes. More expensive than re-ingest because extraction is re-done; prefer re-ingest when the extracted content is fine and only the LLM compile needs another pass.

See also: Re-ingest, Ingest, Source

S

Search

Finding Neurons in a Brain. Every Brain has keyword search (FTS), and a Neuron whose title exactly matches your query is always ranked first. A Brain can additionally have hybrid search switched on, which also matches on meaning — so "opening hours" can find a Neuron that says "we're open from 9". Hybrid search is off by default and is turned on per Brain.

See also: FTS, Chunk, Chat, Audience, Top-K

Slug (slugify)

A URL- and filename-safe version of a title, produced by a deterministic transformation called slugification: lowercase everything, replace spaces with hyphens, strip punctuation, and fold non-ASCII characters to their closest ASCII equivalents (æ→ae, ø→oe, å→aa). Examples: "Yin og Yang" → yin-og-yang, "Orphans + Stale" → orphans-stale, "Christian Broberg" → christian-broberg. Slugs are the canonical address of a Neuron inside a Brain — the file is <slug>.md, the URL is /kb/<kb-slug>/neurons/<slug>, and a Neuron-link's [[...]] text gets slugified to find its target. Two different titles that slugify to the same string collide on the same Neuron, so the compiler avoids ambiguity by keeping titles distinctive in the source language. The Danish/English bilingual fold recognises that yin-og-yang and yin-and-yang should resolve to the same Neuron when the KB's language is Danish — protecting against LLM drift between og / and.

See also: Neuron, Neuron-link, Trail

Source

An immutable raw document added to a Brain — PDF, Word, PowerPoint, Excel/CSV, Markdown, plain text, HTML, images, a synced web page or a saved conversation. A Source is never edited after ingest; when a changed version arrives it is stored as a new edition of the same Source. Neurons are compiled FROM Sources and cite them.

See also: Neuron, Ingest, Reference

Stale Neuron

A Neuron that hasn't been touched in a long time (default 90 days). Not automatically wrong, but the most likely to have drifted from what its Sources now say. Lint flags it so the Curator can confirm it's still accurate, refresh it from the Source, or archive.

See also: Neuron, Lint, Source

Superseded

A Neuron that has been replaced by a newer one. It happens automatically when two Neurons contradict each other and one clearly wins — clearly higher confidence and at least as many Sources behind it — or when a new version of the same Source arrives. The old Neuron is kept for history, but chat no longer uses it and the graph tones it down. If neither side clearly wins, the contradiction goes to the Curator instead.

See also: Contradiction, New version becomes canon, Memory fading, Archive, Typed Edge

T

Tenant

An isolated workspace — its own Brains, Sources, credits and members. Nothing crosses from one tenant to another. You can belong to several tenants and switch between them from the pill in the top bar; new members are invited by email with a magic link.

See also: Brain, Credits, API key

Top-K

The K best matches from a similarity search — the standard way to limit how many results a query returns. Trail uses top-K = 5 by default for contradiction-lint: when scanning a Neuron, take the 5 most-related peers (via FTS) and pair-compare. Higher K = better coverage but more LLM calls (cost grows linearly). Lower K = faster + cheaper but might miss contradictions hiding in less-obvious peers.

See also: Peer, FTS, Lint, LLM

Trail

The product: a knowledge system that compiles your Sources into linked, cited Neurons a Curator approves, so people and AI can ask it questions. Trail is organised as Tenant → Brain → Neuron. (A single knowledge base used to be called "a Trail"; since September 2026 it is called a Brain.)

See also: Neuron, Source, Curator

Typed Edge

A Neuron-link that carries a named semantic relation, so the graph isn't just "A links to B" but "A is-a B" or "A contradicts B". Authored as [[target|edge-type]]. Seven recognised types: cites — bare mention, weakest relation, the default for every plain [[link]] and every older link; is-a — hierarchical specialisation (Labrador is-a Dog); part-of — composition (Keyboard part-of Laptop); contradicts — an explicit disagreement between two claims, feeds the contradiction-lint detector directly; supersedes — versioning (Constitution-1953 supersedes Constitution-1849); example-of — a concrete instance of an abstract concept (Pythagoras example-of Mathematician); caused-by — causal dependency (Flood caused-by Dam-break). The compile-prompt teaches the LLM when each type applies; the backlink extractor records the type in the DB on save; the Graph view colours edges by type with a legend-chip row, and the relationships API exposes a ?type= filter for targeted queries ("show me everything this Neuron contradicts"). Turning a bare [[link]] into a typed one is a drop-in edit — no schema migration, the default stays cites for anything un-typed.

See also: Neuron-link, Backlink, Contradiction, Reference

W

Work item

A task, bug, milestone or decision kept in a Brain next to the knowledge, with a status (open, in progress, blocked, done), an assignee and a due date. Link it to Neurons with [[Neuron-links]] and the related knowledge follows it into chat and compile.

See also: Neuron-link, Brain, Neuron
